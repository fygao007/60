# 业务需求生成前端页面规则

本规则用于把用户提供的业务需求，转换为符合 PC 框架布局与设计系统风格的前端页面。

## 工作原则

1. 用户给的是业务需求，不要求用户描述视觉细节。
2. 页面外壳默认遵循 `pc-framework-layout-spec.md`。
3. 基础控件优先使用本地设计组件库。
4. 若需求未指定输出形式，先生成 HTML 预览页。
5. HTML 预览确认后，再生成 React 业务页面。

## 需求解析顺序

收到业务需求后，按以下顺序提取信息：

1. 页面名称
2. 页面类型
3. 页面角色与业务目标

## 页面类型判定

### 列表 CRUD 页

出现以下关键词时，生成列表页：

- 增删改查
- 列表
- 查询
- 分页
- 表格
- 父子表格
- 子表
- 展开明细
- 行内操作
- 批量操作

默认结构：

- 左侧框架导航
- 顶部 Tab
- 页面标题区
- 查询筛选卡片
- 工具栏
- 表格
- 分页
- 弹窗/抽屉预览
- 空态预览

若目标页面需要贴近教学 6.0 低代码系统默认列表态，表格优先使用 `DSDataTable variant="lowcode"`，并按需要开启 `draggable`。该模式默认匹配「首列拖拽手柄、第二列复选框、右侧表格工具图标、46px 行高、文字操作列」的低代码表格形态。

### 父子表格页

出现以下关键词时，优先使用 `DSParentChildTable`：

- 父子表格
- 主子表
- 展开子表
- 展开明细
- 学院-专业、批次-任务、方案-规则、组织-人员等层级数据

默认结构：

- 查询筛选区
- 工具栏
- 父级表格
- 展开按钮列
- 内嵌子表容器
- 父级行操作与子级行操作
- 子表空态
- 分页

父级和子级字段应分别配置 `parentColumns` 与 `childColumns`；父级操作使用 `parentActions`，子级操作使用 `childActions`。
若展开内容不是标准表格，使用 `expandedRowRender` 自定义内容；若需要控制展开状态，使用 `expandedKeys` 和 `onExpandChange`；若子表可勾选，开启 `childSelectable` 并传入 `selectedChildKeys`。

当 MasterGo 页面表现为「表头 -> 分组条 -> 父级汇总行 -> 缩进子表」时，使用 `layout="grouped"`。分组文本使用 `groupTitleKey` 或 `renderGroupTitle`，父级汇总行优先使用默认字段 `degree/type/tag`、`title/name`、`code/number`、`count/countText`，复杂内容使用 `renderParentSummary`；主表头直接配置 `childColumns`，如稿件已在主表头展示字段，可设置 `showChildHeader={false}` 避免重复表头。

### 审核页

出现以下关键词时，生成审核页：

- 待审核
- 已审核
- 通过
- 不通过
- 退回
- 审核状态

默认结构：

- 状态 Tab：待审核 / 已审核 / 全部
- 查询筛选区
- 审核列表表格
- 操作列固定显示审核动作
- 批量审核按钮

### 表单页

出现以下关键词时，生成表单页：

- 新增
- 编辑
- 填报
- 保存
- 提交
- 分组表单

默认结构：

- 页面标题区
- 分组卡片
- 表单字段两列布局
- 底部固定操作栏

### 导入向导页

出现以下关键词时，生成导入向导：

- 导入
- 智能导入
- 上传文件
- 字段映射
- 校验

默认结构：

- 步骤条
- 上传区域
- 模板下载说明
- 字段映射表
- 校验结果
- 导入完成结果
- 底部操作按钮

React 页面优先使用：

- `DSImportWizard`：导入向导整页组合。
- `DSImportSteps`：导入步骤条。
- `DSImportUpload`：上传文件和模板下载区域。
- `DSImportMappingTable`：模板字段到系统字段的映射表。
- `DSImportValidationPanel`：错误、警告、通过数量与明细。
- `DSImportResult`：导入完成结果页。

### 详情页

出现以下关键词时，生成详情页：

- 详情
- 查看
- 基本信息
- 记录
- 流程

默认结构：

- 页面标题区
- 状态摘要
- 描述列表
- 分组内容卡片
- 操作按钮

## 字段转组件规则

| 字段/需求关键词 | 默认组件 |
|---|---|
| 名称、标题、关键词 | Input |
| 类型、状态、是否 | Select |
| 日期、年月、时间 | DatePicker 样式输入 |
| 备注、说明 | Textarea |
| 是否启用 | Tag / Switch |
| 状态 | Tag |
| 文件 | Upload 区域 |
| 操作 | Link Button |
| 批量操作 | ButtonGroup |

## 表格列规则

- 若需求包含“操作”，默认操作列放在左侧或右侧，按参考图倾向左侧。
- 序号列宽 64px。
- 操作列宽根据按钮数量调整，通常 160-220px。
- 状态字段使用胶囊 Tag。
- 风险/限制提示使用黄色 Tag。
- 表格行高默认 46px。
- 表头背景默认 `#F7F8FA`。

## 操作规则表达

业务规则必须显式体现在页面中：

- 不可删除：按钮置灰 + 黄色提示 Tag。
- 删除确认：生成确认弹窗预览。
- 复制后进入编辑：在操作说明或提示区体现。
- 预览需选人：生成预览弹窗/选择教职工区域。
- 审核通过/不通过/退回：生成操作按钮与状态标签。

## 空态规则

如果页面是列表页，必须同时准备空态结构：

- 插画占位
- 空态标题
- 空态描述
- 主操作按钮

默认文案格式：

- 标题：暂无{对象名}
- 描述：暂无{对象名}，请点击【新增】创建

## HTML 输出规则

HTML 预览页应满足：

- 单文件可打开
- CSS 内联在 `<style>` 中
- 不依赖构建工具
- 能完整展示默认态和关键状态
- 文件放在 `ui-demo` 目录
- 文件名使用页面语义英文，例如 `scheme-management.html`

## React 输出规则

React 页面应满足：

- 页面放在 `pm_agent/pc/src/pages/{Module}/{Page}/index.jsx`
- 样式放在同目录 `index.css`
- 使用 `@wisedu/design-system` 组件
- 在 `router/index.jsx` 注册路由和菜单
- 修改后运行 `npm run build`

## 默认页面审美

- 背景：`#F5F7FB`
- 卡片：白底、浅边线、8-10px 圆角
- 主色：设计系统主色
- 表格：浅灰表头、行高 46px
- 筛选：卡片内栅格布局
- 操作：主操作按钮靠右，查询按钮靠筛选区右侧
